# Security policy

- Identify trust boundaries and preserve authentication, authorization, least privilege, secret storage, network exposure, and auditability.
- Keep credentials, tokens, private keys, and sensitive values out of source, ordinary logs, artifacts, plans, and outputs.
- Review CI identities, workload identities, database roles, cloud permissions, and service accounts at the affected boundary.
- Distinguish a demonstrable exposure from a theoretical hardening opportunity.
- Avoid broad wildcard permissions when narrower current permissions are practical.
- Make credential rotation, revocation, and failure behavior operable.
